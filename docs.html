Payerkart API documentation

One REST API for eligibility verification and claim status, with consistent JSON in and out across payers. This page is an overview; the full reference and sandbox keys are shared when you request access.

Request sandbox access →

Basics

  • Base URL: https://api.payerkart.com/v1
  • Format: JSON request and response bodies
  • Versioning: versioned endpoints from day one (/v1)
  • Writes: idempotent, so safe to retry
  • Async: webhooks or polling for long-running checks and claim status changes

Authentication

Send your API key as a Bearer token. Keys are scoped and revocable from the admin console. Sandbox keys return canned payer responses.

Authorization: Bearer $PAYERKART_KEY

Verify eligibility

POST /v1/eligibility: check a patient's coverage with a payer. Identify the patient by member ID, or by name and date of birth plus payer details.

curl https://api.payerkart.com/v1/eligibility \
  -H "Authorization: Bearer $PAYERKART_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient": { "member_id": "W12345678" },
    "payer": "auto-detect",
    "service_type": "office_visit"
  }'

# 200 OK
{ "status": "active", "plan": "PPO Gold", "copay": 25 }

A full response also carries plan dates, deductible used and remaining, network status and coverage by service category. Field-level definitions are in the full reference.

Get claim status

GET /v1/claims/:id: returns where a claim stands with the payer (submitted, in review, paid or denied). Denials and follow-up requests include a plain-language reason and suggested fix. Remittance detail is linked once the claim is paid.

Webhooks

Register a webhook to be notified when an asynchronous eligibility result is ready, when overnight batch verification flags a patient, and when a claim's status changes. Polling is supported for every case.

Errors and rate limits

Errors come back as a structured code plus a plain-language message, never raw EDI. Common cases:

SituationWhat you get
Member ID not foundStructured "not found" result: recheck the member ID
Coverage inactiveInactive status with the termination date
Payer outageA "payer down, retry" result; retries with backoff are built in
Too many requestsHTTP 429 with documented rate limits

Sandbox

Test keys and canned payer responses let you build and test the full flow before go-live, with no payer contracts to negotiate first.
