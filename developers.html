Built for the team wiring it into your EHR.

Request sandbox access →How the EHR adapter works
Authentication

Scoped API keys

Send your key as a Bearer token. Keys are scoped, revocable from the admin console and every request made with them is logged.

Eligibility

Verify coverage

Send the patient (member ID, or name and date of birth plus payer details) and get coverage, plan dates, copay, deductible and network status back.

Claim status

Track a claim

Look up where a claim stands with the payer. Rejections come back with a plain-language reason and a suggested fix.

Webhooks

Async when it matters

Get notified when a long-running eligibility check finishes, when overnight batch verification flags a patient, and when a claim's status changes.

Errors

Structured, readable errors

A code plus a plain-language message, never raw EDI. Payer outages, invalid IDs and inactive plans each have their own result.

Reliability

Versioned and idempotent

Versioned endpoints, idempotent writes, retries with backoff and clear rate limits with 429 responses.

An eligibility request

The request shape running in production. Sandbox keys return canned payer responses.

curl https://api.payerkart.com/v1/eligibility \
  -H "Authorization: Bearer $PAYERKART_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "patient": { "member_id": "W12345678" },
    "payer": "auto-detect",
    "service_type": "office_visit"
  }'

# 200 OK
{ "status": "active", "plan": "PPO Gold", "copay": 25 }
